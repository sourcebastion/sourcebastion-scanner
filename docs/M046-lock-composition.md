# M046 S03 — canonical Python lock evidence

This slice extends the built-in `compose_source` API with Pipfile specification 6,
Poetry lock 2.0/2.1, uv lock 1 revision 3, PDM lock 4.5.0 and pylock 1.0 registry
subsets. It does not wire the scanner route, produce an SBOM, run matching or
complete S03. Node, Go, Rust and restricted provider integration remain open.

One S02 discovery and held Source admit the exact lock bytes, followed by final
epoch validation. The same deadline and semantic ledger cover grammar visits,
conditional variant comparisons, candidate filtering and retained records.
No project code, resolver, package installation, registry request or forge API
is executed. Source descriptors bind this read, not persistent administrative custody.

Every locked occurrence retains selected PEP440 identity, source/hash/locator,
artifact hashes, scopes, groups, extras and markers. uv registry URI identities
are SHA256 assertions, not authenticated registry evidence or artifact digests.
Poetry optionality is separate from group and marker conditions. Requires-Python
assertions retain their located PEP440 or pinned Poetry dialect. Alternative PDM
targets are not collapsed into an AND expression. No host target is supplied.

Lock inputs have analysis scopes and nullable project ownership. Adjacent manifests
and requirements never lend their root or version selection to a lock table.
Explicit false package markers can exclude a target occurrence; all other locked
activation remains unknown. A source pin is not an installed package.

Each dependency selector remains a typed record, including missing or ambiguous
endpoints. Resolved selectors require exactly one matching canonical edge; child
scopes/groups and PDM exact extra variants remain structurally bound. Unresolved
selectors cannot claim a complete graph. A source edge exists only for an unambiguous entry in the same lock,
with exact uv version/registry selection and PDM extra/group variant selection.
Poetry range tests use only the maintained pure `poetry-core==2.1.3` constraint
grammar, with known grammar caches cleared on every success/refusal path.
No Poetry factory or project loader is invoked. This is a pinned dialect, not a
claim of compatibility with every current Poetry feature.

uv dependency markers are simplified relative to lock Python compatibility;
they are retained with explicit relative semantics and unknown activation even
when a project target is supplied. Duplicate/repeated unproved selector contexts
remain unresolved instead of multiplying edges. Overlapping occurrence variants
remain visible and make input coverage partial. Equal PURLs never erase source,
extra, group or conditional variants. Source edges have unknown installation
activation; graph completeness remains partial or unknown.

Unknown resolver controls, unsafe sources, unsupported lock versions, missing
metadata/artifact evidence and malformed input remain visible in coverage. A
missing-source fragment may retain located package assertions with partial
coverage. A grammar refusal does not silently switch to directory matching.
Shared semantic, retained edge, structure or source epoch failure clears all
consumable records. Per-input grammar omission may retain independent evidence
with partial coverage. Runtime lock hashes bind the pure Poetry wheel for all
four existing CPython 3.14 target locks; no unrelated packages are resolved.

Validation distinguishes package-identity subsets of the frozen corpus from full
rich oracle agreement. Existing corpus folder ownership expectations are not
adopted. Local Python 3.13 evidence is not a native 3.14 receipt. Installed image
probes record all loaded inventory module digests, finite source semantics and
64 repeat digests independently for AMD64 and ARM64. Kernel/resource, whole
pipeline, dependency/license closure and development acceptance remain S06/S07.
