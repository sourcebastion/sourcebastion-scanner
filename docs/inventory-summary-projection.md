# Canonical summary projection

`sourcebastion.inventory.summary_projection.project_inventory` is an inactive
pure helper. No entrypoint, CLI, worker, route or uploader calls it. It takes an
exact typed `Inventory`, validates and serializes it using the authoritative
canonical implementation, reparses only those internally generated bytes with
strict JSON semantics, and returns detached canonical-derived facts. It does
not accept arbitrary JSON or reconstruct a full reported summary.

Profile `sourcebastion.inventory-summary-projection/1` defines recognized inputs
as coverage records whose format is non-null. Unsupported and failed inputs
can be recognized. This count never means supported, parsed or resolved.
Discovered inputs counts coverage records, including missing/refused referenced
inputs, rather than filesystem traversal entries. Parsed count is a distinct
disposition. Selected occurrences require an actual selected version; declared
ranges do not select versions. Evidenced relationships includes conditional
and inactive evidenced edges; it is not the smaller CycloneDX edge projection.

The artifact digest and size describe the internally generated canonical bytes.
Every projected field derives from the same detached snapshot. Returned maps
belong to the caller and carry no authentication. Canonical source, producer,
coverage and environment fields remain validated assertions until independent
execution and source custody evidence binds them.

The helper intentionally omits inventory execution status/diagnostics, scanner
image and plan admission, export status/counters/identity, matching status and
consumer/advisory/recovery/output identities. Later successful export/matching
does not mutate the canonical stage fields. Canonical projection losses and
export omissions have different meanings. Full report, canonical artifact and
exported SBOM validation remain separate acceptance steps.

The caller supplies a shared cancellation/deadline check. It is called before
and after canonical snapshot work, during count loops and before return. This
does not interrupt Pydantic or canonical serialization internally; an admitted
parent watchdog and kernel resources must bound those operations. The helper
adds no budget, process, network access or retry allowance. Typed canonical
limits still apply. Raw-upload grammar and byte/structure admission, a fixed
validator ABI, runtime qualification, persistent association and settlement
remain open. No platform summary schema is imported or copied here.
