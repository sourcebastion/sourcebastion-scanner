# Observed Python distribution metadata

The internal source composer reads bounded `.dist-info/METADATA` through the
maintained packaging Core Metadata parser. Exact Name/Version and an equivalent
directory identity establish an observed distribution record. Original source
bytes, hashes and located headers remain evidence. Nothing imports the customer
package, installs dependencies, executes project tooling or contacts a registry.

An observed metadata file has its own analysis scope. Project root and installed
environment ID remain null; directness, runtime scope and activation stay
unknown. Equal purls in separate metadata files retain separate occurrences.
The record does not prove a running interpreter, importability, shared environment
or application reachability. An explicit environment target does not establish
that the observed installation runs there. Graph fidelity remains partial.

Requires-Dist headers become separate declarations with ranges, markers and
extras. Even an exact dependency pin creates no installed child occurrence or
cross-file edge. Requires-Python remains located applicability, without host
evaluation. Concrete fields remain meaningful when Dynamic lists them; Dynamic
is informational in installed/wheel metadata. Provided extras and informational
Dynamic fields have located projection losses. Deprecated dependency controls,
external requirements and platform controls retain explicit losses and partial
input coverage. URL references are redacted to the existing direct-reference
sentinel; arbitrary metadata prose and URLs are not exported.

RFC822 folding is unfolded before maintained grammar validation. Malformed
headers, structural email defects, duplicate singleton identity, unsupported
fields/versions or contradictory identity refuse that input. Eager validation
fields have lexical complexity bounds before maintained parsing. Source epoch,
deadline and shared budget failures invalidate the operation; independently
valid inputs can survive ordinary per-input syntax refusal. The outer controller
still owns actual resource containment and immutable source custody.

The first adapter supports recognized dist-info metadata only. Bare egg-info and
egg-info/PKG-INFO remain explicitly unsupported because source distributions can
contain the same syntax. No complete ecosystem or installed graph claim follows
from this slice. Public scan routing remains unchanged.

Import-Name/Import-Namespace overlaps refuse ambiguous identity. Valid import
controls remain explicit unassessed identity losses with partial input coverage.
The legal empty Import-Name is retained as the maintained parser's explicit
empty list and receives a located loss. Newer
metadata extra names are checked before normalization. Normalized output fields
must fit the canonical contract before an input can grant occurrence authority.

The installed native proof exercises seventeen finite observations/guards on each
architecture and refuses optimized Python, which could remove its assertions.
Full M046 corpus, pipeline, release and human acceptance remain separate gates.

References: [Core Metadata](https://packaging.python.org/en/latest/specifications/core-metadata/),
[installed projects](https://packaging.python.org/en/latest/specifications/recording-installed-packages/),
[packaging metadata API](https://packaging.pypa.io/en/stable/metadata.html).
