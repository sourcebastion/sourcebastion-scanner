# Maintained Go source parser

This preparation tranche builds a small fixed executable using the already pinned `golang.org/x/mod/modfile v0.41.0` parser and Go1.27.1 module closure. It consumes bounded go.mod bytes from stdin; it does not execute customer Go commands, load project packages, resolve dependencies, read host caches or access a registry. The internal canonical Python adapter accepts only an explicit trusted controller artifact identity, pins an executable descriptor and verifies its SHA before calling it. Executable custody is rechecked on every exit after opening, including execution, timeout and decoding failures; loss or replacement clears mixed-language results. Source hashes and typed responses retain exact directive ordinals/positions; controller Source/ledger/deadline and final epoch checks cover mixed-language composition. Requirements become unversioned declared occurrences and unresolved minimum-version declarations in their explicit module project context. Directness, activation and scope remain unknown; the indirect assertion remains in the private source observation. go.sum remains explicitly unsupported checksum history and cannot resolve any requirement. Missing helper produces explicit unsupported coverage. Runtime image installation remains pending.

`require` versions are normalized source minimums, not selected module versions. The result explicitly reports selected versions and graph as unreported. The [official module reference](https://go.dev/ref/mod#minimal-version-selection) explains why transitive requirements can change selected versions; go.sum is checksum history rather than a lock. Quoted module syntax, indirect flags and exact directive source byte spans come from the [maintained parser](https://pkg.go.dev/golang.org/x/mod/modfile). Replacement/exclusion/toolchain/retraction and other supported controls remain named unassessed directives. Duplicate requirements are retained independently with an uncertainty flag. Unknown future syntax fails strict parsing. No package-to-package edges are inferred.

The native proof explicitly refuses optimized Python (`-O` and `PYTHONOPTIMIZE`), so its checks cannot disappear. The deadline covers blocked input and output; consumers require successful exit and a complete typed document, since a timed-out pipe can contain partial bytes. The executable accepts at most2MiB input/100000 records and64MiB output, and uses the caller remaining deadline (at most150s). Input hashes bind the returned observations to exact supplied bytes. Public library errors and local replacement paths are not projected; the result remains private source evidence. Parent/controller kernel CPU/memory/PID/network controls remain required; parser flags are not a sandbox.

Trusted preparation downloads and verifies the pinned official compiler, hydrates the module graph while online, then verifies/tests/builds offline with unchanged source hashes. Both architectures retain helper binary/buildinfo, compiler and module receipts plus finite offline synthetic probes. These checks do not establish rich corpus agreement, canonical integration, matching, complete SBOM accuracy, licenses/maintenance/resources or M046 acceptance.
