# Static Cargo source observations

This internal adapter reads Cargo manifests and version 3/4 lockfiles locally. It does not invoke Cargo, install packages, evaluate build scripts, contact registries, inspect host Cargo configuration, or resolve a manifest range. The scanner route and M046 acceptance remain open.

The source contract follows Cargo's [lockfile schema](https://github.com/rust-lang/cargo/blob/1fd17bcd77ee9d4883d0a766a5995184a4064ff9/crates/cargo-util-schemas/src/lockfile.rs) and [resolver encoding](https://github.com/rust-lang/cargo/blob/1fd17bcd77ee9d4883d0a766a5995184a4064ff9/src/resolver/encode.rs). Preparation authenticated the immutable Git blob identities and retained those files for review. Cargo's [manifest requirements](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html) are not npm ranges: a declaration such as `1.2.3` is not an exact selected version. Static manifest requirements remain declarations, with no guessed floor version or lock matching. The lexical safe-text guard is not a Cargo range parser or a proof that every observed range is valid.

An explicit package manifest can establish its own project identity and nullable version. Runtime/dev/build/optional declarations, feature requests and safely representable target expressions remain separate source evidence; no host target or feature activation is inferred. Workspace inheritance, alternative dependency sources, manifest overrides and unsupported target expressions remain partial coverage. A workspace package version is not borrowed from another file automatically. Legacy underscored dev/build tables are retained for editions through 2021 (including the default 2015 edition); the hyphenated spelling takes precedence when both exist, with the ignored alias recorded as coverage uncertainty. Edition 2024 legacy tables and unknown/inherited editions cannot produce complete coverage. Legacy `[project]` and `default_features` remain unsupported partial cases. These boundaries follow the pinned [manifest accessors](https://github.com/rust-lang/cargo/blob/1fd17bcd77ee9d4883d0a766a5995184a4064ff9/crates/cargo-util-schemas/src/manifest/mod.rs) and [Rust 2024 migration rules](https://doc.rust-lang.org/edition-guide/rust-2024/cargo-table-key-names.html).

A lock input has a distinct analysis scope, nullable root, unknown directness/scopes/activation, and independently located occurrences. Registry/sparse registry entries with supported names and exact selected versions can be matching candidates. Local/path/git/replaced identities remain blockers in the source selector index without acquiring a registry matching identity. All source entries remain distinct; equal purls do not deduplicate them.

A lock dependency's serialized package ID selects within that exact lock input. Omitted version/source qualifiers are allowed only when the recorded selector has one unique source entry. Fully qualified selectors require exact version and asserted source string identity. Exact duplicate lock identities make coverage partial even without incoming references. Duplicate or ambiguous entries, refused identities, and missing endpoints produce unresolved selectors without edges. A same-name package from a different lock input cannot fill a gap. Source URI identities are hashed; no URI normalization, credential payload or downloaded artifact authentication is implied. A supplied SHA256 checksum is an asserted artifact digest, not a verification that the artifact was downloaded or examined.

The stdlib TOML decoder is preceded by a bounded lexical nesting check and followed by a bounded structural walk. Every input and semantic phase shares the controller Source, remaining deadline, record limits and semantic ledger. Invalid source syntax is local to its file. Global budget or source epoch uncertainty clears consumable mixed-language records. This is not proof of kernel CPU/memory/PID/network isolation; the separately reviewed outer boundary must enforce those limits.

Supported corpus agreement, installed native proof, full support-matrix characterization, export/matching, production integration, whole-pipeline resource/license/maintenance acceptance, platform persistence and human development testing remain open. Targeted tests and repeated canonical digests do not replace those acceptance gates.
