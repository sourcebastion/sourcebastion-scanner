# Bounded source-aware Yarn observations

The internal source composer observes registry packages and source-selected dependency edges in classic Yarn v1 and modern Yarn lock formats 4–10. This does not run Yarn, install dependencies, evaluate project hooks, read host resolver configuration, or query a forge/registry. The public scanner route remains unchanged; S03/M046 acceptance remains open.

Classic syntax uses the unmodified standalone generated SYML grammar from maintained `@yarnpkg/parsers` 3.1.0, pinned to immutable Yarn Berry commit `923f69827c77fe5cf4f6c28c0cab3c02a256abf0`. Only its generated parser, grammar source, and root BSD-2-Clause license are shipped. The full Yarn runtime and parser package dependencies are not shipped. Preparation checked registry archive integrity, the npm registry metadata signature, and immutable grammar/license source identity. This is not an upstream generated-code reproducibility or Sigstore claim. The private vendor manifest pins every shipped upstream file; the helper verifies those identities before parsing.

The classic helper uses fixed `/usr/bin/node`, a minimal environment, trusted packaged entry point, no dynamic code generation, a bounded stdin protocol, and the caller's remaining deadline. It rejects duplicate or unsafe mapping keys during the upstream grammar's mapping construction and bounds output nodes, depth, strings, and serialization reservation before output. The helper preserves the upstream parser's object identity for one entry's alias keys. Separate entries with equal contents remain separate occurrences. Modern syntax uses the existing bounded, data-only YAML loader, refusing aliases, anchors, tags, duplicate/merge keys, invalid Unicode scalars, and excessive structure before construction.

Both paths retain the exact source entry and descriptor keys. An edge is selected only by its literal source descriptor; maintained npm-semver 7.8.5 checks compatibility after source selection. Equal package names, versions, or purls never select or merge endpoints. Overlapping descriptors are ambiguous even when one owning entry is refused. Modern entry and endpoint-selecting dependency descriptors require an explicit `npm:` protocol. Bare peer ranges are admitted as peer declarations by their explicit field semantics and maintained npm grammar; they never select an endpoint. No missing protocol, registry setting, workspace identity, or peer/virtual resolution is inferred. A classic entry must have at least one descriptor with valid maintained npm range grammar before its name can become a matching identity; an unsupported npm alias cannot promote its alias name to the actual package. Combined alias keys may share only their actual source entry.

Each lock input has a distinct analysis scope. Application roots remain nullable; occurrence directness, installed activation, and project ownership remain unknown. Source runtime/optional/peer selectors are retained separately. Peer selectors remain unresolved because installed peer context is unproved. Missing required resolution remains a partial fragment while independently observed name/version may survive. Workspace, virtual, patch, file/git, alias-identity changes, platform conditions, and unsupported controls remain explicit partial coverage. A modern Yarn cache checksum is not relabelled as npm tarball integrity. No downloaded artifact verification is claimed.

All parsing, source validation, occurrences, selectors, and edges share the same admitted Source, deadline, and semantic ledger as the other adapters. A source file's invalid syntax is local; a global budget or source epoch failure clears consumable mixed-language records. Unsupported private source expressions are represented by fixed reasons and source-derived hashes without publishing credential URLs.

The targeted fixtures and installed-image probe are finite checks. The 64-record repeatability run proves repeatability only. Complete rich corpus agreement, full ecosystem coverage, exported SBOM matching, production integration, kernel isolation, whole-pipeline resources, maintenance/license acceptance, platform persistence, and human development acceptance remain open.
